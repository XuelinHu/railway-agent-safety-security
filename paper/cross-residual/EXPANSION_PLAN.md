## 1. 目标与完成标准

本轮后续工作的目标，是将目前的短篇双栏稿扩展为结构完整、方法定位准确、实验分析充分的约 10 页研究论文。页数包含摘要、正文、公式、图表和参考文献，不包含单独提交的作者标题页。

| 项目 | 当前情况 | 后续目标 | 验收口径 |
|---|---|---|---|
| 模板 | 已经使用 CAS 双栏 `cas-dc` | 保持现有模板 | 不通过缩改页边距、行距、字号实现目标 |

## 2. 当前论文与结果的核查结论

### 2.1 当前题目和方法

英文题目：

**Gated Score-Residual Adaptation for Efficient Cross-Domain Named Entity Recognition**

方法并不是新建深层交叉残差编码器，而是在冻结通用 GLiNER 与其领域适配副本之间构造候选实体的分数残差：

\[
\Delta(c)=s_1(c)-s_0(c),\qquad s_f(c)=s_0(c)+\alpha\Delta(c).
\]

当前门控是通过开发集搜索得到的领域级标量，不是样本级或实体级神经门控网络。正文、标题与结构图都必须遵循这个事实。

### 2.2 现有真实结果可以支持什么

| 配置 | 五领域平均严格 typed-span F1 |
|---|---:|
| 冻结通用模型 | 62.93% |
| 普通领域适配 | 75.44 ± 0.30% |
| 分数残差融合 | 75.60 ± 0.24% |

关键解释：

1. 普通领域适配相对冻结模型约提升 12.51 个百分点。这是目标领域监督的收益，不能全部归为所提残差策略的创新收益。
2. 残差策略相对匹配的普通适配模型平均提升约 0.159 个百分点，四舍五入为 0.16 个百分点。
3. 三次运行的领域宏平均增量均为正，不意味着每个领域的每次运行都提升。
4. 现有配对检验以三次运行的五领域宏平均为单位，`p=0.06738`，95% 区间约为 `[-0.0282, 0.3465]` 个百分点，不能写成统计显著提升。
5. `status.json` 记录总运行时间为 562.117 秒，即约 9.4 分钟；这是已有程序记录，尚不能代替独立的端到端性能审计。
6. CrossNER 的五个领域是同一基准下的五个领域，不应写成五个独立公开基准。

### 2.3 当前证据可以直接复用的文件

| 文件 | 已有内容 | 可支持的分析 |

当前训练脚本在内存中生成候选分数，但未见将逐句候选分数与完整门控搜索结果写入上述结果目录的逻辑。当前汇总文件不能反推出以下内容：实体类别混淆、逐实体纠错、真实 PR 曲线、未见实体表现、门控完整响应面。

这类分析需要先核查本地检查点是否完整；完整则补推理，不完整则重跑相应模型。不能从均值和标准差人工生成“原始预测”。

## 3. 扩写之前必须处理的科学与实现问题

### 3.1 正视与加权融合的代数等价性

现有公式可以改写为：

\[
s_f(c)=(1-\alpha)s_0(c)+\alpha s_1(c).
\]

因此：

- 当 `0 ≤ α ≤ 1`，它在数学上就是分数的凸组合。
- 当 `α = 0.5`，它就是等权平均。
- 当 `α = 1`，它就是普通领域适配的分数。
- 当 `α > 1`，它是沿适配方向的线性外推，分数可能超过 `[0,1]`。

当前 Related work 中“score averaging ignores the direction of adaptation”等排他式措辞需要改写，因为残差表达与一定条件下的加权平均等价。不能通过换一种公式写法宣称完全不同的模型类别。

创新重点应放在任务适配、可拆解的纠正证据、开发集控制和系统验证。若计划提出非线性或候选自适应新门控，那是新的方法版本，必须另行实现和验证；本计划不默认升级为已实现功能。

### 3.2 候选截断与解码顺序需要核对

现有 `prediction_cache()` 使用 `predict_entities(..., threshold=0.03)` 获取每个分支的输出，再对并集进行融合。待核对：

1. 该接口是否在返回之前已进行重叠消解、候选去重或其他解码。
2. 被接口筛掉的候选，不能描述成模型从未打分的候选。
3. “缺失候选赋零”是否只是对截断输出的近似，而非其真实原始分数。
4. 两个分支分别去重后再取并集，是否会重新产生重叠实体；最终是否有一致的平坦 NER 解码。
5. 论文应明确“原始全候选分数融合”还是“分支已输出候选的融合”。

若检查后改变了候选池或解码规则，必须为所有对照使用一致新规则并重新评估。旧协议与新协议的数值不能拼成同一张主结果表。

### 3.3 开发集和测试集边界

脚本目前通过 `label_inventory(train, validation, test)` 提取标签集合。已知官方任务标签集合与利用测试集标注信息不是一回事，需调整来源与措辞：

- 优先采用官方预定义标签表；没有则说明训练/开发来源及未覆盖标签的处理。
- 不应直接扫描测试金标决定模型输入标签，然后笼统声称“测试标签完全未使用”。
- 标签名称、超参数、门控、阈值和训练停止决策的来源分别记录。
- 测试表现不得反向用于挑选门控、训练轮数或仅保留有利模型。
- 现有脚本提前生成冻结模型的测试预测，不自动等于泄漏；关键是任何测试结果是否影响了后续选择。后续流程应将测试汇总与调参明确隔离。

### 3.4 通用模型预训练污染风险

“冻结模型未接受本次目标训练”不等同于“该模型从未接触 CrossNER”。后续应检查 GLiNER-small-v2.1 的模型卡、发布版本及公开训练数据说明，确认是否包含 CrossNER 或重合数据。无法排除时如实说明，不能宣称完全未见领域的零样本泛化。

### 3.5 训练目标与重复运行用词

- 核对安装版本 GLiNER 的实际损失：是否为 BCE、focal loss、负采样或其他加权形式。当前论文中的普通 BCE 只能在与实现一致时作为真实训练目标。
- 三次训练均加载同一预训练检查点，应称为“不同随机性的三次适配运行”，而不是三个不同预训练初始化。
- 基础冻结预测在各次运行中重复使用，不能当作三个独立训练的零样本模型来扩大样本量。
- 论文可保留必要训练设置：骨干、学习率、批大小、训练预算、运行次数、候选/解码规则。具体运行标识与缓存路径放复现资料，不能以“代码细节”为由删掉全部可复现条件。

### 3.6 效率证据必须区分训练与推理

“融合模块无新训练参数”并不意味着“双分支推理没有额外成本”。需要分别报告：

- 单分支参数量与双分支部署参数量。
- 单分支与融合方案的推理吞吐、平均延迟、显存峰值。
- 是否缓存冻结分支输出；在线新文本不能直接套用离线缓存成本。
- 训练、开发集推理、搜索、测试推理的耗时边界。
- GPU 计时的预热与同步，避免异步执行造成低估。

若没有充分的效率对照，题目中的 “Efficient” 建议移除。

## 4. 标题—三个贡献点—摘要的统一设计

### 4.1 推荐标题

优先保留一个与真实实现一致、不过度承诺的标题：

**Validation-Gated Score-Residual Adaptation for Cross-Domain Named Entity Recognition**

中文：**面向跨领域命名实体识别的验证集门控分数残差适配方法**。

理由：明确门控来自开发集；明确残差在分数空间；不让审稿人误以为引入了新的深层残差编码器；效率由实测结果支撑，而不是先写进标题。

此处只是标题建议，本轮没有改题目。如果补充实验确实证明效率优势，可保留原标题中的 “Efficient”。

### 4.2 建议三个贡献点

| 贡献 | 准确表述方向 | 必须对应的证据 | 避免的夸大 |
|---|---|---|---|
| C1：分数级适配分解 | 将通用证据与目标适配改变量显式分开，形成可分析的推断表达 | 结构图、等价关系、候选级实例 | 宣称新 Transformer、新型深层交叉残差网络 |
| C2：开发集控制的残差融合 | 用开发集确定适配改变量的介入程度，考察其相对固定融合与单分支的价值 | 固定门控消融、联合搜索热图、配对增量 | 将所有适配收益归给门控，或称其必然优于平均融合 |
| C3：面向小样本领域适配的系统证据 | 从数据分布、错误转移、重复运行和成本解释方法的适用条件 | 长尾/长度分析、纠错统计、重复实验、成本测量 | 把图表数量本身当创新，或声称普遍最优 |

建议的贡献措辞是“提供一种可解释分解和实证分析框架”，而不是“首次解决跨领域识别”。是否能写“首次”必须建立在充分检索之上。

### 4.3 摘要重写顺序

保持一个自然段，建议约 200–250 个英文词，服从目标期刊要求：

1. 问题：小样本目标适配需要平衡通用证据与领域专门化。
2. 方法：冻结参考、目标适配、分数差、开发集门控。
3. 协议：官方五领域、严格边界与类型匹配、独立适配重复。
4. 主结果：报告最终平均 F1，同时明确相对普通适配的增量。
5. 机制结果：只填后续实际验证的纠错、长尾或门控发现。
6. 价值：说明适用场景与可检查性；不要承诺显著或普遍优势。

不必在摘要逐一列出五个领域全部均值；可将空间用于真实机制发现。不能在补分析前预写“显著减少长尾错误”等结论。

## 6. 公式扩展方案：约 18–22 个有效编号

不为达到数字而把 Precision、Recall、F1 等基础定义重复拆成许多编号。下列是候选公式主题，正式编号在排版时统一生成，允许合并。

| 候选编号主题 | 内容 | 为什么需要 | 实施前约束 |
|---|---|---|---|
| E1 | 目标域数据集、句子与类型集合定义 | 统一任务符号 | 标签集合来源明确 |
| E2 | typed-span 候选 `(b,e,y)` 与合法区间 | 定义严格抽取对象 | 区分字符右端开闭与 token 索引 |
| E3 | 标签条件分数 `sθ(c)` | 连接骨干与融合 | 不杜撰 GLiNER 内部结构 |
| E4 | 实际监督训练目标 | 说明适配如何发生 | 先核验实际库实现 |
| E5 | 参数冻结与目标优化 `θ1 = Adapt(θ0,Dtrain)` | 分清两个分支 | 不暗示独立预训练 |
| E6 | 候选并集与缺失分数处理 | 让融合可复现 | 如为截断近似须明确 |
| E7 | `Δ(c)=s1(c)-s0(c)` | 核心分数残差 | 与实现一致 |
| E8 | `sf=s0+αΔ` | 核心融合 | 说明门控为领域级 |
| E9 | `sf=(1−α)s0+αs1` | 公开与加权融合等价性 | 不是第二个独立创新 |
| E10 | `α=0,1` 的端点性质 | 支撑分支消融 | 与固定候选、解码条件对应 |
| E11 | `∂sf/∂α=Δ` | 解释门控影响方向 | 只是分数敏感性，不是性能单调性 |
| E12 | `sf−s1=(1−α)(s0−s1)` | 解释相对适配分支的纠正 | 不是准确率提升保证 |
| E13 | 阈值与最终解码规则 | 定义输出集合 | 与平坦/重叠处理一致 |
| E14 | 开发集上 `(α*,τ*)` 联合选择 | 隔离调参与最终评估 | 明确并列最优的确定规则 |
| E15 | 严格 P/R/F1 定义组 | 明确评估口径 | 零分母处理明确 |
| E16 | 领域宏平均 | 区分五域平均与合并微平均 | 与已有汇总一致 |
| E17 | 匹配运行增量 `δr=F1fusion,r−F1adapted,r` | 聚焦残差实际收益 | 不混合不同运行 |
| E18 | 均值与样本标准差 | 解释误差条 | 不能把 SD 标为 CI |
| E19 | 配对置信区间或 bootstrap 过程 | 表达不确定性 | 明确运行/句子抽样单位 |
| E20 | 训练实体频次与分组定义 | 支撑长尾和未见实体分析 | 仅使用训练频次建组 |
| E21 | 净纠错量 `C+−C−` | 解释哪些预测发生改变 | 与集合定义一致 |
| E22 | 推理成本分解 | 支撑效率讨论 | 必须结合实测，不能只有大 O |

可在方法中简短解释以下边界，而不必再增加编号：

- `0 ≤ α ≤ 1` 且输入分数位于 `[0,1]` 时，融合分数仍在此区间。
- `α > 1` 时不再必然是概率，因此称为“score”，不直接称为校准概率。
- 分数沿某方向变化，不代表 F1 随门控单调变化，因为阈值和结构解码会改变最终实体集合。
- 即便 `α=1` 包含在搜索空间中，开发集不劣也不保证测试集不劣。
- “calibration” 若用于概率校准，需要校准指标；只有阈值选择时，优先称为决策控制或分数融合。

### 7.2 模型图必须重画到什么程度

1. 输入只画一次 sentence 和 label inventory，然后分成两路。
2. 左路标明 frozen general recognizer，参数 `θ0` 和锁定标志。
3. 右路标明 target-adapted recognizer，参数 `θ1`；训练监督只指向右路。
4. 两路分别输出候选与分数，经候选对齐后进入差值节点。
5. 明确差值方向是 `adapted − general`，不能画反。
6. 标出 `αd` 由 development set selection 提供，不画成已经训练的神经网络。
7. 通用分数以 identity path 连接加法节点。
8. 最后画 threshold/decoder 和 typed spans。
9. 训练流与推理流采用不同线型，图例移至无数据区域。
10. 不画未实现的 attention、CRF、交叉特征层或候选自适应门控。

### 7.3 数据分布图细节

基础统计至少包括：句子数、实体数、类型数、句子 token 长度中位数及分位数、实体 token 长度、每句实体密度、训练集中每类实体数。

长尾图的标签频次排序以训练集确定。不同领域的标签库存不同，不应生硬把所有标签放在一个共用横轴上；可采用领域分面或显示每域高频/低频比例。

未见实体分组以训练实体表面形式为依据，明确大小写和空白规范化。可同时检查严格字符串和规范化字符串，但不能选择更有利的定义而不披露。

### 7.4 结果图的视觉和语义规范

- 主 F1 柱图不截断纵轴夸大微小提升；小增量放单独配对差值图并标单位为“百分点”。
- 有序变量才优先画折线，如优化步数、阈值、训练比例、实体长度区间。
- AI、Literature、Music 等无序领域更适合点图/柱图。现有按领域连接 P/R 的图不是“PR 曲线”，应更名或替换。
- SD、标准误和 CI 必须明确区分；三次运行显示原始点比只放误差条更透明。
- 采用白底、色盲友好配色、统一字体；按最终单栏/双栏尺寸检查文字可读性。

### 9.2 B 级：读取官方数据，不需要训练

- [ ] 核对官方仓库版本、文件数量及哈希。
- [ ] 统计标签数、类别频次、句长、实体长度和实体密度。
- [ ] 检查 BIO 合法性及字符/token 映射的一致性。
- [ ] 检查训练—开发—测试完全重句与规范化重句。
- [ ] 保留官方划分作为主评估；如有重叠，单列敏感性分析，不擅自删除后仍称官方划分结果。
- [ ] 固定训练频次分箱边界，例如 0、1–2、3–5、6–10、>10；最终边界先按支持量审查，不根据测试增益挑选。

### 9.3 C 级：复用模型，补推理和离线分析

执行前先核对 15 个适配检查点与冻结模型是否存在且可加载。Git 忽略不代表本地缺失，本轮未完整枚举所有忽略权重。

建议保存以下内容：

```text
domain, split, run_id, sentence_id
tokens, character_offsets, gold_spans
candidate_start, candidate_end, candidate_type
general_score, adapted_score
candidate_emission_or_filter_status
alpha, threshold, fused_score, final_decision
model_revision, dataset_hash, decoding_protocol
```

金标字段和可用于选择的开发集字段应在逻辑上分离，避免分析脚本误用测试金标选择参数。检查点和大规模候选缓存继续本地忽略；发布轻量汇总、必要复现配置和允许发布的样例。

| 对照配置 | 门控处理 | 阈值处理 | 目的 |
|---|---|---|---|
| 冻结分支 | `α=0` | 开发集选择 | 无目标适配参考 |
| 普通适配 | `α=1` | 开发集选择 | 必须保留的主 baseline |
| 等权融合 | `α=0.5` | 同样开发集选择 | 回答是否优于简单平均 |
| 固定阻尼 | 如 `α=0.75` | 同样开发集选择 | 分离固定阻尼与搜索收益 |
| 固定外推 | 如 `α=1.25` | 同样开发集选择 | 观察放大适配的行为 |
| 开发集门控 | 预先固定搜索空间 | 联合选择 | 当前策略 |
| 同阈值诊断 | 不同门控 | 使用预先定义的共同阈值 | 分离门控和阈值的影响，不作为唯一主比较 |

注意：可学习权重的线性加权融合，在相同候选和搜索空间下与当前方法可能完全等价。应解释等价性，不把它伪装成独立且更弱的竞争方法。

完整搜索面只用开发集绘制。测试集上报告预先规定对照的表现，不依据测试热图选出最好门控。

错误分析建议采用互斥、可复现匹配规则：完全正确、同边界错类型、同类型边界偏移、其他重叠混合错误、漏检、伪检。多预测对一金标时先固定一对一匹配优先级，避免同一错误重复计数。

分组 P/R/F1 必须定义假阳性属于哪个组：例如按预测 span 的长度或训练表面形式频次分组；若只按金标分组，则应报告分组召回而不是伪造完整 F1。

### 9.4 D 级：少量新增训练，按预算选择

优先级从高到低：

1. **一致协议复跑**：若候选解码、标签来源或训练目标核对导致实现修正，优先重跑原 5 域 × 3 次矩阵，而不是混入旧数值。
2. **第二编码器家族**：选择公开轻量 encoder+token/span head，对目标监督训练形成外部对照。不能用明显弱、随机初始化模型来刻意衬托预训练模型。
3. **低资源曲线**：在少数预先选定领域，用 25%、50%、100% 的嵌套训练子集考察趋势，分层抽样并保持标签覆盖记录。
4. **增加适配重复**：从 3 次增至 5 次，如时间允许；必须报告所有预先指定运行，不能“跑到显著即停止”。
5. **第二独立基准**：在许可证、BIO 定义、模型预训练重叠风险与时间允许时增加一个公开 NER 基准。CrossNER 内再选一个领域不算新增独立基准。

历史自建数据和旧转换数据不默认加入。加入之前需审查来源、标注协议、任务定义和旧结果口径，不能因为文件存在就作为当前正式实验。

不再引入生成式大语言模型作为主方法或填充性 baseline。公开论文中的数值可在相关工作讨论，不能直接冒充本实验重跑结果。

### 9.5 三小时预算的执行方式

历史 9.4 分钟只能作为预估参考，不能据此承诺所有新增实验一定完成。后续先计时一个代表性任务，再决定可承受的矩阵。

| 时间窗口 | 推荐内容 | 超时处理 |
|---|---|---|
| 0–20 分钟 | 数据/权重审计、小规模加载与推理计时 | 若关键协议有问题，先修复，不盲目启动大矩阵 |
| 20–70 分钟 | 必要的一致协议复跑或全量候选缓存 | 若权重可复用，优先补推理 |
| 70–115 分钟 | 门控消融、误差/分组分析、性能计时 | 跳过非必要大搜索，不删已完成不利结果 |
| 115–155 分钟 | 第二骨干或小样本曲线，二选一优先 | 无余量则标注未完成，不填假数 |
| 155–180 分钟 | 汇总、完整性校验、保存、结束训练任务 | 留出落盘时间，禁止无止境运行 |

这是未来计算窗口的预算，不包含文献阅读、DOI 核验、整稿写作与视觉审稿耗时。

如未来启动实验，应采用非阻塞任务管理、单 GPU 队列、定期落盘和失败续跑。每项任务保存完成状态；避免当前脚本全部循环结束才写主结果导致中途失败后无法复用。

### 10.4 每篇 DOI 的核验流程

1. 从出版商、ACL Anthology、Crossref、DataCite 等来源取得题录，不靠语言模型补 DOI。
2. 检查 DOI 标准格式并规范化，去掉引用尾部标点、URL 前缀重复等问题。
3. 访问 `https://doi.org/<DOI>`，记录核验时间、状态和最终落地 URL。
4. 进一步核对落地题录的标题、作者、年份、期刊/会议、卷页，与 BibTeX 一致。
5. HTTP 成功不是充分条件：页面可能是错误页、机器人验证页或另一篇文章，必须核对内容。
6. 遇到 403/429/超时，标记待核验，通过出版商及注册元数据交叉确认，不直接判定不存在。
7. DOI 可解析不等于全文免费。用户要求的线上可查应落实为题录和文献身份可验证。
8. 有正式出版版本时优先正式 DOI。只有 arXiv DOI 的候选不能假装是期刊发表；建议不计入“20 篇正式 DOI 文献”的最低保障，除非用户明确接受。
9. 无法匹配的条目剔除或保持候选状态，不写入最终正式参考文献表。
10. 最终 PDF 的参考文献中可见 DOI 或可点击 DOI 链接，不只在 `.bib` 后台保存。

## 11. 结果分析具体怎么写

### 11.1 主结果

分成三个层次：冻结到适配的变化、适配到融合的变化、各领域差异。用配对增量明确残差贡献，不仅比较最终方法与较弱零样本基线。

保留 P/R 的精确口径，避免从“precision 高于 recall”直接断定唯一错误原因。专业术语漏检、边界错误和类型混淆需要错误统计支持。

### 11.2 数据分布与性能

先描述训练量、标签频次和实体长度，再观察对应分组表现。只允许写“与……现象一致”“提示……可能影响”，除非有受控消融足以支撑因果。

只有五个领域时，不宜对领域均值做高阶拟合或据此声称普遍规律。优先实体级、句子级分组分析，并报告各组支持数。

### 11.3 消融

不能只写“移除模块后降低，说明模块有效”。应检查：

1. 哪个配置减少了何种信息或决策自由度。
2. 降低体现为精度、召回还是边界/类型错误变化。
3. 是否多个运行方向一致，是否有领域例外。
4. 固定融合是否已获得大部分收益。
5. 联合阈值搜索是否解释了表面门控增益。

若没有明显改善，应收缩贡献陈述或归入适用条件，不能反向篡改表格。

### 11.4 讨论与结论

按此前偏好，Discussion 保持一节三个自然段：

- 第一段：方法带来的主要价值，以及消融/纠错证据如何支持。
- 第二段：不同分布下的适用性、部署成本与非生成式特点。
- 第三段：简短说明小增益、单基准/骨干、门控粒度等局限及下一步。

结论不机械重复所有表格，概括任务、方法、最可靠数字和适用范围。数据声明保持简洁，不新增基金或 AI 声明，不擅自修改作者信息。
